# Roadmap

This is a direction for discussion, not a delivery promise. The project is an early v0.1 alpha; the owner approved source publication and Apache-2.0 on 2 November 2026. Implemented behavior must be established from the source and recorded verification; a roadmap checkbox is not proof of a feature or deployment.

## Current review scope

The [README](../README.md) and [API contract](api-contract.md) describe v0.1: NL/EN intake and tracking, a single-owner desk, D1 storage, resolved-request retention, optional owner notifications, and hosted booking/payment links. The [release checklist](release-checklist.md) records what has actually been verified and approved. No public release or production adoption is claimed.

## Next verification and adoption

1. Completed locally: security and customer/owner journey review, clean-folder installation, synthetic screenshots, dependency notices, and explicit owner approval of contents and Apache-2.0. See the verification record.
2. The public repository has been created under bradcroes; finish source upload and verify hosted CI. Record the actual result before claiming a hosted check passed.
3. Establish release/support practices and welcome useful external contributions. Hosted deployment requires its own resource and cost approval.

## Possible later work

- Recovery or revocation for lost or exposed customer tracking links.
- A practical export/deletion workflow and clearer operator backup procedures.
- Accessibility and language improvements based on actual user feedback.
- Staff accounts and role design, if evidence supports moving beyond one owner.
- Carefully scoped notification or mailbox integrations, with explicit provider and privacy controls.

There is no commitment to multi-business tenancy, payment automation, inbound email, attachments, or staff permissions. Proposals should start with a concrete user problem and a review of security and operational cost; see [CONTRIBUTING.md](../CONTRIBUTING.md).
